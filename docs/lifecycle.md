# 公告生命周期：从采集观察到效力判断

本文档描述在原始采集之上新增的解释层。设计约束来自业务侧的一次事故：
同编号公告撤回后重发，采集工具抓到了两个页面，却无法说明哪个还有效，
项目经理按已撤回的许可日期安排了进场。本层的目标是让每一次效力判断
都能交代依据，并且在证据不足时保持待核，而不是编出一个答案。

## 分层

```
原始归档（archive.py，不变）      只追加的捕获：状态、头部、原文、接收时间
        │  重放（interpret）
派生库（derived.py）              声明 statements / 解释进度 incorporated /
        │                          观察口径 capture_scope / 留档 snapshots
        │  查询时计算（judge）
效力判断（lifecycle.py）          纯函数：同一知识截止重算结果不变
```

- 原始归档只追加，业务解释层独立演进；派生库是归档的确定性重放，可删除重建。
- 判断不在写入时固化，而在查询时按知识截止即时计算，因此"当前判断"与
  "历史时点判断"走同一条代码路径，历史时点不需要事先留档也能复查。
- 留档（snapshots）是唯一固化的判断，写入后不可改写（数据库触发器拒绝
  UPDATE/DELETE），用于保存进场依据。

## 声明：保留来源说了什么

每条来源记录成为一条声明（statement），归属一次捕获：

- 身份三元组 `authority`、`notice_id`、`edition` 原样保留；同一编号在不同
  发布机关下是互不影响的两条生命周期。
- `kind`（种类）、`replaces`（原文更正/替代引用）、`published`（声明的发布
  日期）、`precision`（声明的时间精度）逐字保留，不做归一化；日级精度
  不会被补成午夜时间戳。
- 完整原文 `payload` 随声明保存，冲突展示和留档都直接引用原文。
- 同一版本的多次观察归并为 sightings；内容不一致记为 content_drift 冲突，
  两份原文都保留，不做取舍。

## 排序：只认原文引用

公告之间的先后只来自原文中的 `replaces` 引用，构成版本链：

```
first ──被替代── withdraw ──被替代── reissue      （链头 = reissue）
```

- 抓取顺序不参与排序。搜索缓存里晚到的旧页只是已替代版本的又一次
  sighting，不会让许可重新生效。
- 来源声明的发布日期也不参与排序。日级精度下同日的两份公告若互不引用，
  先后未知，保持待核；日期不相同的互不引用公告同样待核，仅以 hints
  形式提示"声明日期不同"，供人工核查，不据此定先后。
- 抓到明确撤回文本后，链头为撤回即判 withdrawn；真正的重发页通过
  `replaces` 引用撤回页而恢复效力，判断输出完整链，展示它与撤回的关系。

## 状态

| 状态 | 含义 |
| --- | --- |
| `unobserved` | 知识截止内没有任何该公告的声明 |
| `effective` | 唯一链头是有效类声明（issued/reissued/corrected） |
| `withdrawn` | 唯一链头是撤回类声明（withdrawn） |
| `pending` | 存在阻断性冲突，不宣布任何一方有效 |

阻断性冲突：competing_heads（多份公告互不引用）、content_drift 落在链头、
reference_cycle（引用成环）、unrecognized_kind（链头种类不在已知范围，
不猜测其效力）。非阻断提示：dangling_reference（引用的版本尚未观察到
原文）、非链头版本的 content_drift。冲突输出均附相关声明标识，`--explain`
与留档会带上对应原文。

## 覆盖口径：未见到 ≠ 不存在

"没有替代页"有两种含义，判断中分开表述：

- `not_observed`（未见到）：目前没有任何观察显示替代页，但也没有完整
  列表观察佐证——单页抓取、搜索缓存都属于此类。
- `absent_as_of`（截至某次完整列表观察不存在）：某次标记为
  `enumeration` 的完整列表观察列出了该公告且没有替代页。判断给出依据
  捕获号；随后若条件请求返回 304（内容未变），口径时点顺延到 304 那次
  捕获（horizon_capture）。

完整列表的身份由采集方在捕获时以 `--scope enumeration` 声明，属于观察
口径的元数据，不从内容猜测。"不存在"仅指"来源自己的当前列表截至该次
观察没有"，不超出这个含义。

## 查询入口

- 当前时点：`status --authority X --notice Y`（`--explain` 附全部原文）。
- 历史知识时点：`status --as-of-capture N` 或 `--as-of-time ISO`，
  按知识截止重算，回答"当时我们知道什么"。
- 留档：`snapshot save --purpose 进场依据：…` 固化当前判断（含原文与
  知识截止）；`snapshot show/list` 读取留档；`snapshot verify` 按留档的
  知识截止重算并比对摘要，证明记录未被改写且判断可复现。
- 后续更正只会产生新的声明与新的当前判断，不会改写任何留档。

## 矛盾处理

几份声明互相矛盾时（互不引用、同版本内容漂移、引用成环），状态为
pending，冲突清单列出各方版本链与原文，不选择"看起来最新"的页面宣布
解决。解除待核的途径是取得新的证据（含明确引用的页面、完整列表观察），
而不是调整判断规则。

## 限制

- 来源声明只作为声明保存与解释，本层不核验来源本身的真实性。
- `kind` 词表开放，未知种类落在待核而不是被误归类。
- 完整列表的"完整"以来源与采集口径为准；本层如实记录口径依据。
